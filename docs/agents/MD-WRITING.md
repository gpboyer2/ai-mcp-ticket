# md 写作规范

> 本文件是「md 文档怎么算合格」的唯一权威，由 `.githooks/pre-commit` 强制执行。

## 一、为什么管

AI 写 md 有个通病：先说一堆背景，再用「综上所述」收个尾，读者翻三屏才看到结论。这类空话删掉之后句子的意思一点不变，纯粹浪费 reading time 和 token。

## 二、硬规则

`scripts/check-md-filler.mjs` 只认一批**删掉后意思不变**的填充词，出现即拦：

`综上所述` `总而言之` `总的来说` `总体而言` `总体来看` `值得注意的是` `需要强调的是` `需要指出的是` `值得一提的是` `不难发现` `众所周知` `由此可见` `在当今` `随着人工智能` `随着技术` `话不多说` `言归正传`

代码块（``` 围起来的部分）里的内容不检查。

## 三、刻意不拦的词

词表宁可小，不可误杀。下面这些在技术文档里有实际含义，一律放行：

| 词 | 为什么不拦 |
| --- | --- |
| 闭环 | 描述业务流程时是真在用的词 |
| 颗粒度 | 描述时间粒度、数据粒度时准确 |
| 打法 | 交易、策略语境下的正常说法 |
| 换句话说 | 用于重述结论，有信息增量 |
| 首先 / 其次 | 单独出现是正常行文，也可能是正常列举 |
| 显而易见 | 可作定语（「显而易见的错误」），不限空话 |

## 四、怎么写才不被拦

1. 开门见山：第一行就说结论，别铺垫。
2. 能列成条目的，不写成段落。
3. 有数字的写数字，别写「效果显著」。
4. 删掉过渡句：读者不需要你告诉他「接下来我们看看」。

## 五、怎么执行

| 场景 | 命令 |
| --- | --- |
| 每次 `git commit` | 钩子自动跑，只查这次新增的 md 行 |
| 全仓库体检 | `pnpm check:md` |
| 绕过（不推荐） | `git commit --no-verify` |
